    01Overview

    Why this review happened

    REF// VEC-OVERVIEW

    VEC is a real, currently-in-flight engagement — a self-service portal where enterprise and SMB Wireline and Wireless customers manage orders, service inventory, repair tickets, billing, and their own users. It's paired with an internal Agent Console used by care, help-desk, and sales teams to act on a customer's behalf when self-service can't finish the job — the two share one design system because they enforce the same entitlement rules. Before any screen work started, discovery ran across the roles that actually own this product's outcomes — the business analyst tracking completion metrics, the project manager owning the delivery roadmap, the tech lead who has to build whatever gets designed, and the associate director accountable for the P&L this portal sits inside.

    • Raise self-service completion — more tasks finished in the portal without an agent, measured per journey rather than per visit.
    • Deflect assisted volume — fewer calls, chats, and Agent Console transactions for tasks the portal already supports.
    • Shorten time to order — one-pass intake and visible pricing remove the rework loop between submit and provisioning.
    • Grow digital revenue — catalog, quotes, and upgrade paths become discoverable inside the workspace, not only through sales.
    • Lower cost to change — one design system across every module and both portals cuts duplicated build and QA effort.
    Product
    VEC, built on Monarch 3.0 — 8 core modules, 50+ self-service actions, 3 primary user types.
    Client
    Verizon, delivered through Innova Solutions.
    My role
    Lead Experience Designer — discovery, synthesis, and the AI-first redesign direction.
    Scope
    Business + user discovery, a 5-category UX audit, and a phased AI-first redesign roadmap.

    02Audit Framework

    Two questions, asked of every screen

    REF// VEC-FRAMEWORK

    VOC volume said where to look; the audit said why it was happening. Every pain point was walked screen-by-screen against the same two questions, before any redesign direction was proposed:

    Question 1

    What's actually causing this — not the symptom a customer reports, but the underlying mechanism?

    Question 2

    What's the smallest fix that resolves the cause, rather than papering over the symptom?

    Running all five pain points through that lens surfaced three failure modes that repeated across the product, not just within one module:

    State gets lost

    Sessions, in-progress forms, and ticket sync all drop information the user already gave the system.

    Errors go unexplained

    Payments and tickets fail or close silently, with no reason surfaced to the customer.

    One record at a time

    The interface assumes a single line or invoice, in a product built for enterprise-scale, multi-line accounts.

    Evidence gapThe audit itself was documented as a large annotated screen-by-screen review — the source file runs to dozens of individual annotated screens. Rather than reproduce those, this section and the findings below synthesize the real cause-and-fix pairing the audit produced.

    06Review Findings — Positives

    The existing experience already does some things right

    REF// VEC-POSITIVES
    • Simple cases already get deflected. The existing assistant asks which module an issue belongs to and resolves straightforward cases with FAQ content before they ever reach an agent.
    • Entitlement rules are already unified. The customer-facing portal and the internal Agent Console already enforce the same entitlement logic — a real structural foundation to build the redesign on, not a from-scratch problem.
    But…729 logged VOC items across five pain points say the portal doesn't yet complete enterprise-scale tasks on its own. It routes and deflects — it doesn't consistently act.

    08Strategy

    Silent closures break the one promise self-service makes

    HML
    REF// VEC-STRATEGY · 85 of 729 VOC items

    Audited cause: the support-ticket fault-selection dropdown freezes the ticket wizard, tickets don't sync to the dashboard in real time, and agents can close a ticket with no customer confirmation. A portal whose value proposition is "handle this yourself" loses that proposition the moment it resolves something without telling the person who filed it.

    Fix direction: fix the dropdown state bug, add real-time API sync between the ticket wizard and dashboard, and require a mandatory customer sign-off before any ticket is marked resolved.

    09Information Architecture

    The invoice lives in an email, not in the product

    HML
    REF// VEC-IA · 263 of 729 VOC items

    Audited cause: invoices post 8+ days late, and arrive only via an async email link rather than living inside the portal itself. The guest payment tool then crashes on multi-invoice sessions with no explanatory error. The core information a billing module exists to surface isn't architected to live where the user already is.

    Fix direction: instant in-portal PDF access the moment an invoice posts, a refactored multi-bill payment handler, and specific error messages on failure instead of a silent crash.

    10Navigation

    Finding something means knowing which world it's in first

    HML
    REF// VEC-NAVIGATION · 43 of 729 VOC items

    Audited cause: search fields don't support wildcards, and Wireline and Wireless assets are managed in isolated views, forcing an admin to repeatedly switch account context just to look for one thing. Affinity mapping on the raw feedback set surfaced that this clustered with the login/session issues above — "which world am I in" is a navigation problem as much as it is an access one.

    Fix direction: wildcard search across every inventory table, plus a unified toggle header so switching between Wireline and Wireless doesn't mean leaving and re-entering a different view.

    11Interaction

    The interface loses state without telling you

    HML
    REF// VEC-INTERACTION · 178 of 729 VOC items

    Audited cause: a ≤30-minute inactivity timeout purges in-progress forms with no warning, and 2FA email delivery lags long enough to break the login attempt itself. One real customer routed around this entirely — paying without logging in, out of frustration.

    Fix direction: extend session duration, add local state caching so a timeout doesn't erase unsaved work, and cut 2FA delivery to under 5 seconds.

    12Detailed Design or Presentation

    Built for one record at a time, used for enterprise scale

    HML
    REF// VEC-DETAILED · 160 of 729 VOC items

    Audited cause: disconnecting multiple lines requires 27 repeated manual steps per line, with no bulk upload path and no control that copies entered data across lines. The form itself is correctly designed for a single-line consumer account — it was never adapted for the enterprise-scale, multi-line accounts VEC actually serves.

    Fix direction: a bulk CSV/Excel disconnect tool, "copy to all lines" form controls, and updated validation logic that handles a batch rather than one record.

    13Other Known Issues

    Issues that didn't fit one category cleanly

    REF// VEC-OTHER
    • Module drift. Each of the eight modules had drifted into its own visual language, its own navigation pattern, and in places its own separate mobile treatment — a structural issue underneath every category above, not specific to any one of them.
    • "Login" and "navigation" don't separate cleanly. Affinity mapping on the raw feedback repeatedly grouped session/login complaints together with confusion navigating between Wireline and Wireless — evidence that these are one design problem seen from two angles, not two independent bugs.
    14UX Goal

    What if the AI workspace were the product?

    REF// VEC-GOAL

    The redesign direction converges on one thesis: what if the AI workspace were the product, and the forms-and-tables UI were the fallback — not the other way around? Today, a scripted bot asks which module an issue belongs to, deflects simple cases, and routes everything else to a queue. It routes conversations; it doesn't complete tasks.

    Acts — the assistant completes the task, not just routes it
    Explains — every answer cites the record it came from
    Hands off with context — an agent never makes the customer repeat themselves
    Stays within guardrails — same entitlement rules as the structured UI, confirmation before anything commits
    15Recommendations

    Functional and useful today — not yet persuasive at enterprise scale

    REF// VEC-RECOMMENDATIONS

    The redesign could have gone four different technical routes to fix the module-consistency problem underneath these findings. Each was scored on effort to ship versus how strategically it set up the AI-first direction — not picked by preference.

    Low effort / Low strategic value
    • Embedded Wrapper — iframe container, zero changes needed from tool teams
    High effort / Low strategic value
    • No candidate scored here — every option had a strategic angle
    Low effort / High strategic value
    • Design System SDK — shared token library, tools feel native — chosen for Phase 1–2
    High effort / High strategic value
    • AI Abstraction Layer — AI queries tool APIs directly, no UI inconsistency possible
    • Micro-Frontend Shell — full Module Federation rebuild, fully consistent UX and shared state

    The chosen path takes the low-effort, high-value option first (the shared design system) while keeping the two higher-effort, higher-value options — the AI abstraction layer and the micro-frontend shell — as the Phase 2–3 direction once the foundation is in place. The broader rollout uses the same logic at portfolio scale: a five-phase plan (Unify → Optimize → Modernize → AI-Enable → Future-Ready) that opens with a formal complexity/priority assessment across every application before committing engineering effort.

    Ask in plain language→Act, with guardrails→Explain and cite→Hand off with context

    17Outcome

    Key Learnings

    Key Learnings

    The chatbot wasn't the problem — its ceiling was

    The existing assistant already handled simple routing fine. The redesign wasn't "add AI," it was "let the AI actually finish the task instead of forwarding it."

    Affinity clusters and business goals should argue with each other

    "Deflect assisted volume" as a business goal and "silent ticket closures" as a customer pain point are the same problem seen from two sides — the redesign had to satisfy both readings at once, not pick one.

    Confidentiality is a design constraint too

    Writing this case study honestly — real numbers, real names where cleared, recreated rather than copied screens — took the same discipline as the redesign itself: say exactly what's true, and mark plainly what isn't shown.
